# 本文

AIチャレンジ365、Day17。

Day5〜6で、Threadsの自動投稿に挑戦しました。

▼ 当時の記事
Day5｜「これ自動化できない？」とAIに聞いたら、作業のやり方そのものが変わった

Day6｜AI初心者6日目。Threadsの自動投稿が本当に動いた

ただ、当時の記事は「本当に動いた！」という感想が中心で、どうやって作ったのかをほとんど書けていませんでした。

そして今回、この自動投稿の仕組みを**Claudeで作り直しました。**

今は、寝ている間にネタが集まって、朝と夜に投稿が自動で出ていきます。

- かかった時間：約30分
- 使ったもの：Claude（Pro・月20ドル）、GitHub、Threads API（Meta公式）、Mac
- 追加の費用：0円（すでに払っているClaude Proの範囲内。GitHubとMetaは無料）

この記事では、どういう仕組みなのか、実際にやった手順、つまずいたポイントをまとめます。

## この記事で分かること

1. Threads自動投稿の全体像
2. 実際の設定手順（つまずいた所つき）
3. Claudeに投稿文まで書いてもらう方法
4. 今のThreadsの数字

## 全体像：何がどう動いているのか

最初に全体像を書いておきます。僕も最初はここが分かっていなかったので、混乱しました。

📷 `images/threads-flow.webp`（Threads自動投稿の全体像）

```
① Threads と GitHub をつないでおく（最初に1回だけ）
   ↓
② 毎朝、Claude が投稿文を2本書く
   ↓
③ 投稿文が GitHub の「投稿待ちフォルダ」に入る
   ↓
④ 7:30 と 20:30 になると、GitHub が自動で Threads に投稿する
```

自分がやるのは①だけ。①は最初に一度設定すれば終わりです。

1日の流れにすると、こうなります。

📷 `images/threads-day.webp`（自動投稿の1日）

| 時刻 | 担当 | やること |
|---|---|---|
| 0:47 | Claude | noteの売れている有料記事をリサーチして、レポートに保存 |
| 5:52 | Claude | 前日の作業記録とリサーチを読んで、投稿文を2本書く |
| 7:30 | GitHub | 朝の投稿 |
| 20:30 | GitHub | 夜の投稿 |

寝ている間にネタが集まって、起きる前に投稿文ができていて、朝と夜に投稿される。そんな流れです。

出したくない投稿があれば、投稿時刻までに「投稿待ちフォルダ」からファイルを消すだけで止められます。

## 準備するもの

- Threads のアカウント
- Meta for Developers のアカウント（Threads に投稿する「入口」を使うために必要。無料）
- GitHub のアカウント（決まった時間に投稿を実行してくれる場所。この使い方なら無料の範囲で動きます）
- Claude（仕組みづくりと、毎日の投稿文づくり。僕は Claude Pro（月20ドル）を使用）
- PC（僕は Mac。Meta と GitHub の設定画面は項目が多いので、PC の方が楽です）

使っている道具は3つだけです。

| 道具 | 役割 |
|---|---|
| Claude | 仕組みを作る／毎朝投稿文を書く |
| GitHub | 投稿文を置いておく／決まった時間に投稿を実行する |
| Threads API | Meta 公式の「Threads に投稿するための入口」 |

## 手順1：AIに「今どうなってる？」から聞く

いきなり設定を始めるのではなく、まず Claude にこう聞きました。

> Threadsの自動投稿ってどうなってる？

すると Claude が、僕のこれまでの作業記録を調べて、

- 前回作った自動投稿は「外部の予約投稿ツール」で動いていること
- Claude 側には自動投稿の仕組みがまだないこと

を教えてくれました。そのうえで、「Threads 公式の API を使えば Claude 側で作れる」という提案が出てきたので、

> Claude側で自動投稿の仕組みを作って

とお願いしました。

ここで良かったのは、**「どのツールを使うか」を自分で調べて選ばなくてよかった**ことです。今の状況を聞く → 提案をもらう → お願いする、の3ステップで仕組みづくりが始まりました。

## 手順2：Claude に仕組みを作ってもらう

Claude が作ってくれたのは、この4つです。

1. **投稿するプログラム**：投稿待ちフォルダから1件取り出して、Threads に投稿する
2. **時間になったら動かす設定**：毎日 7:30 と 20:30 に、GitHub が 1 を実行する
3. **合鍵を自動で延長する設定**：Threads の合鍵（アクセストークン）は 60 日で切れるので、月2回自動で延長する
4. **設定手順書**：Meta と GitHub で僕がやることを日本語でまとめたもの

プログラムの中身は僕には読めません。でも、Claude が「本物の Threads の代わりに練習用の偽物を相手にして、ちゃんと投稿できるか」まで確かめてくれていました。

## 手順3：Threads と GitHub をつなぐ（最初に1回だけ）

ここだけは自分でやる必要があります。

1. Meta for Developers でアプリを作り、「Threads に投稿していい」という権限を付ける
2. 自分の Threads アカウントを「テスター」として登録し、Threads 側で招待を承認する
3. 「合鍵（アクセストークン）」を発行して、GitHub の Secrets（パスワードを隠して保存する場所）に登録する

📷【Meta の権限設定画面】
📷【GitHub の Secrets 画面（※トークンの中身は写さない）】

Meta や GitHub の設定画面は、正直、初めて見ると何がなんだか分かりません。英語の項目も多いです。

でも、Claude が作ってくれた手順書の通りに、上から順番に進めていったら、**なんだかんだ30分くらいでできました。**

途中で分からなくなったときは、今の画面のスクリーンショットを Claude に送って、

> 今この画面です。次はどこを押せばいい？

と聞くだけ。Day5で覚えたこのやり方が、ここでも役に立ちました。

## 手順4：投稿文も Claude に書いてもらう

投稿文を書くのも Claude に任せています。お願いしたのはこれだけです。

> 投稿文もClaudeが作る仕組みを設定して

すると Claude から、3つ質問が来ました。

| 質問 | 僕の答え |
|---|---|
| 作った投稿文は、確認してから出す？そのまま出す？ | そのまま出す（気になるものは消せばいい） |
| 1日に何件投稿する？ | 2件 |
| 投稿のネタは何から作る？ | 自分の作業記録、note のリサーチ |

さらに、途中でこう付け足しました。

> AI副業に関する共感や問いかけも入れて

その結果、毎日こんな2本が作られるようになりました。

| 時刻 | 内容 |
|---|---|
| 7:30 | 前日に作ったもの・試したことの報告 ＋ AI副業への共感と問いかけ |
| 20:30 | note リサーチで見つけた「実績なしでも売れる理由」 ＋ AI副業への共感と問いかけ |

投稿文の書き方は、Claude が「書き方ルール」としてまとめてくれました。たとえば：

- 文字数：150〜300 文字くらい（Threads の上限 500 文字は絶対に超えない）
- 最初の1行で興味を引く
- 最後の1行は、答えやすい質問にする
- ハッシュタグは1つだけ（#AIチャレンジ365）
- **事実でない数字や成果は書かない**（「月〇万円稼げた」などの盛った話は禁止）
- 本業の話は書かない

特に「事実でない数字は書かない」は、自分の名前で発信する以上、絶対に入れておきたかったルールです。

## つまずきポイント：Claude の自動実行が「保存できない」状態だった

Threads の仕組みを作っている途中で、Claude がもう一つ問題を見つけてくれました。

毎日 note の売れている記事をリサーチしてもらっていた自動実行が、**9月28日から結果を保存できていなかった**んです。リサーチ自体は毎日動いていたのに、最後の「保存」のところで権限のエラーになっていました。

原因は、自動実行が毎回「何も持っていない新しい部屋」で始まっていて、保存先の GitHub に書き込む許可を持っていなかったこと。

Claude が「保存先をはじめから持っている専用の部屋」で動くように作り直してくれて、解決しました。

「動いているように見える」と「ちゃんと結果が残っている」は別物だと学びました。自動化したものも、たまに中身を確認するのが大事です。

## やってみて分かったこと

- **「どうなってる？」と聞くだけで、次にやることが決まる。** 自分で調べてツールを選ぶより、今の状況をAIに見てもらう方が早かったです。
- **難しそうな設定も、手順書通りに進めればなんとかなる。** Meta や GitHub の画面は最初こそ戸惑いましたが、30分で終わりました。
- **自動化したものも、たまに中身を確認する。** リサーチが保存されていなかったのは、Claudeに言われるまで気づきませんでした。
- **止める方法を最初から用意しておく。** 「ファイルを消せば投稿されない」というシンプルな止め方があるので、全部自動でも安心して任せられます。
- **ルールは人間が決める。** 「事実でない数字は書かない」のように、ゆずれないことは最初にルールとして入れておきます。

## 今のThreadsの数字

| 時点 | 閲覧数 | フォロワー |
|---|---|---|
| Day7 | 77 | 1人 |
| Day17（今日） | 9,300 | 68人 |

10日前は閲覧数77、フォロワー1人でした。

自動投稿で毎日欠かさず投稿できていることに加えて、自分から他の人の投稿にコメントしたり交流したりもしているので、どれがどれだけ効いたのかははっきり分かりません。

ただ、Day15でも書いた通り、Threadsは自分から交流した日ほど閲覧が増えます。投稿を自動にして空いた時間を、交流に回せているのは大きいと思っています。

**「投稿は自動、交流は自分で」**というのが今の結論です。

次は、自動で作られた投稿のうち、どんな投稿が見られているのかを数字で確認して、書き方ルールを改善していきます。
